# 知识版本与问答检索联动

日期：2026-10-20。本轮将“启用知识版本”接入问答检索和知识图谱浏览，替代此前仅在知识工作区生效的行为。

## 使用方式

1. 打开“知识审核与版本管理 → 版本发布与回退”，发布并启用版本。
2. 页面显示“问答检索版本”。此后开始的新一轮问答和知识图谱查询使用该版本。
3. 每条回答顶部显示知识版本名称、版本 ID；命中缓存时显示“缓存命中”。历史回答保留原标识。
4. 点击“回退上次启用”，新问答和知识浏览恢复到对应版本。若回退到未启用发布版的状态，则使用环境配置中的基线图谱（当前为 kg_v2）。

无需修改 .env 或重启即可启用和回退。正在生成的回答固定使用开始时选择的版本，不随过程中版本切换而混用其他快照。切换后打开“知识图谱”会刷新版本并清除旧图节点，已发布记录以条件性知识节点呈现，连线不改写为无条件疗效或因果。

## 实现范围

| 文件 | 作用 |
|---|---|
| `agent/core/graph/runtime_version.py` | 每轮绑定不可变版本、校验指纹、任务及线程上下文传递 |
| `agent/core/graph/snapshot_repository.py` | 校验发布快照，提供条件性记录检索及知识浏览适配 |
| `agent/core/graph/project_workbench.py` | 启用和回退前校验快照，提供当前问答版本 |
| `agent/tools/graph_tool.py`、`retriever.py` | 所有 Agent 共用同一个绑定版本；移除旧工具的独立版本选择路径 |
| `agent/core/graph/evidence_report.py` | 用药报告支持发布记录、编号、来源、适用条件及参数 |
| `agent/agents/orchestrator.py`、`diagnosis_agent.py`、`treatment_agent.py`、`drug_review_agent.py` | 使用版本绑定；显式“仅做药物资料审查”直接进入药物审查；来源分开标明；单药/类别背景不作为药物对直接关系 |
| `agent/core/workflow/state.py`、`graph_manager.py` | 保存版本及用户原始输入；跨版本清理旧生成结论、工具结果及混合摘要 |
| `app/service/chat_service.py`、`app/infra/cache.py` | 每轮版本固定、缓存隔离、上下文指纹、SSE 版本信息和失败标志 |
| `app/service/knowledge_graph_service.py` | 普通知识图谱浏览与问答共用版本解析 |
| `front/clinical_cds/src/App.vue` 与图谱组件 | 显示每条回答的版本和缓存命中，刷新浏览版本及管理页指示 |

发布快照通过项目内部数据和来源校验后才能使用，不直接启用未发布的工作数据。没有发布版本时才使用配置基线；已选中的发布版本缺失、损坏或来源不一致会报错，不暗中返回其他版本结果。Neo4j 的 kg_v2 数据及原始冻结台账没有覆盖，GraphRepository 的原始版本白名单仍保留；发布快照由独立适配器读取。

## 缓存与历史

- 每个不可变版本使用独立的缓存集合，标识同时包含发布版本 ID、内容指纹和检索协议版本。新缓存不查询旧公共预热答案。
- 缓存命中还绑定用户、会话历史内容和本轮长期背景，避免相同问题在不同病例上下文中共用答案。历史无法读取时生成独立缓存范围。
- 回退到内容相同的 A 版本，可以命中 A 的有效缓存；B 的缓存不会用于 A。缓存不可用时继续推理，不回到旧缓存集合。
- 切版时保留可识别的用户原始消息，去掉旧模型回答、工具内容和混合摘要，并重新执行当前版本的检索。新增 `user_messages` 归档让升级后的原始输入不因摘要而丢失。
- 长期记忆改从用户输入提取，使用新的 `userfacts_v1_` 命名空间。旧版混合用户/模型内容的长期记忆保留在库中，但不再注入当前问答；新用户背景可跨版本保留，并标明其是用户陈述而不是知识证据。
- 升级前若历史只剩混合摘要，无法可靠还原其中的用户原话，该摘要不带入新版；必要背景需要重新确认。此轮没有删除旧数据库记录。

## 验收与界限

新增 17 项版本联动回归，覆盖 A→B→A、每轮固定、线程传递、缓存集合及上下文隔离、用户原始消息保留、长期记忆来源、损坏拒绝、浏览同步、失败不缓存部分输出及显式药物审查路由。

最终结果：全量 209 项后端测试通过；前端类型检查与构建通过；真实本机版本切换验收 8 项通过，工作区接口复核 18 项通过。浏览器确认管理页问答版本、回答版本及缓存命中标识与普通图谱版本一致。后端有既有 LangChain 弃用提示，构建有既有依赖注释及包体积提示。管理页截图见[版本联动](KNOWLEDGE-VERSION-MANAGER.png)，回答截图见[回答版本标识](KNOWLEDGE-VERSION-ANSWER.png)。

真实本机验收脚本为 `scripts/verify_knowledge_version_link.py`：使用无患者信息的药物资料问题，先验证 A 的实际回答和缓存，再临时退回一项，发布/复用 B、启用 B，检查指定记录编号不再出现；回退 A 后验证记录恢复及 A 缓存命中。结束后恢复该条目原状态、意见和原启用版本。验收 B 作为历史版本保留，不删除发布记录。证据见[验收 JSON](KNOWLEDGE-VERSION-LINK-ACCEPTANCE.json)。

版本标识指知识图谱版本。向量指南检索仍是独立的资料库，本轮没有把其全文及大模型参数纳入发布快照；提示词要求分别标明来源，不能声称整份模型回答的所有知识都来自该图谱版本。这轮完成软件版本联动，不代表诊断准确性或临床部署验收完成。

账号与患者级权限、病例管理、真实业务验证、外部文献库版本化等仍需后续工作。当前共享令牌和 user/session 隔离方式没有升级为医院级权限体系。
