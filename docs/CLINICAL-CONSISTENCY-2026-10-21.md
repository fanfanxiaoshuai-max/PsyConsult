# 医学表述一致性专项修复

本轮只处理原验收A08及其复测发现的具体表述问题，不新增业务功能，不恢复已撤销的证据编号、逐条来源清单或评测界面。

结论：本轮所列已复现问题已通过定向修正与复测；保留自然正文，暂不继续增加其他功能。该结论限定于下面的实现与样本，不等于所有未来医学回答均已获得专家批准。

## 已实现的行为

诊断、治疗节点先生成草稿，再检查患者原话、检索资料与草稿是否一致。检查依据只把本会话原始用户陈述作为患者信息，既往模型回答、混合摘要及检索示例均不直接当成患者事实。原始用户陈述不再静默截掉早期轮次；后续更正也按原始顺序提供给检查器。

发现错误时只替换指定行，其他段落保留。行号用于内部定位，不显示给用户。应用替换后用明确规则再次校验；若仍命中规则，仅针对这些剩余问题修补一次，不再发起另一轮自由的医疗方案评价。只有最终正文进入SSE、检查点、下一阶段及缓存；无法完成核对或明确规则仍有矛盾时结束为失败，不返回未经核对的草稿。

这比仅在提示词中要求“不要编造”多了一道实际执行的检查，也增加了正文出现前的等待。它仍是自动化一致性检查，不是专家签字或所有医学结论的正确性证明。

## 具体修复项

| 问题 | 现在的处理 |
|---|---|
| 用“症状3周”推断“应激事件发生于3周前” | 应激源及发生日期仍未知时，不声称已满足起病时间条件；只保留待核实方向 |
| 一处已满足，另一处又说条件未知 | 检查前后矛盾；对已复现的应激时序矛盾另加明确规则拦截 |
| 未提供检查，却写已排除甲亢/心律失常 | 不允许新增这类排除结论；用户确实提供的阴性检查仍保留，不扩大其排除范围 |
| “长时间”被判为确定病程不足 | 未量化时说“尚未确认是否满足”；只有明确3周时才指出未达到GAD数月要求 |
| ICD-11与DSM条件混用 | 保留WHO CDDR的数月必要特征，不套用固定6个月或凑足3项附加症状的阈值；不外推给惊恐障碍 |
| 错误编码或本次没查到就说体系没有编码 | 默认不主动附编码；明确问编码时才核对；本次未核对不等于分类体系不存在 |
| ICD-11被称为推荐一线药物的治疗指南 | 区分诊断分类资料与治疗指南，拦截这类错误归属 |
| “通常/例如/可考虑”变成绝对条件 | 保留原限定，尤其不把适应障碍“通常一个月内”改成所有病例的硬性截止线 |
| 合理的条件性治疗教育被误判为已确诊 | 不把“若确诊后再考虑”当作已经确诊，不给一般心理支持凭空增设必须先确诊的限制 |
| 未报告的情境分布变成患者事实 | 仅有紧张、心慌、失眠时，不断言“呈非情境特异性”，列为待核实条件 |
| 单个产品资料被扩大为全地区批准结论 | 不由有限说明书断言中国全部SSRI/SNRI都没有某适应症，仍按具体产品核对 |
| 由美国标签推出仅美国批准/中国都未标注 | 不能由美国标签推断其他地区没有批准；中国批准与超说明书状态绑定具体产品和版本 |
| 药物建议把未知诊断转成全面用药禁令 | 不因某一诊断未确认就推导全部焦虑症状一律不得用药；保留实际评估与个体方案的区别 |
| 焦虑治疗检索只返回诊断摘要 | 治疗查询继续检索治疗资料，同时带上已核对的诊断条件，不用诊断摘要替代治疗来源 |
| 诊断末行与治疗标题黏连 | SSE与缓存统一保留阶段间空行 |

## 文件位置

- `agent/core/clinical_consistency.py`：原话与资料分离、逐行修补、修正后规则核验、定向修补及失败保护。
- `agent/agents/diagnosis_agent.py`、`treatment_agent.py`：草稿不直接向用户流出，仅发送核对后的正文。
- `agent/core/clinical_reference.py`、`mock_data/icd11_anxiety.md`：WHO CDDR诊断资料及适用范围。
- `agent/tools/vector_tool.py`：诊断摘要与治疗文献检索的分流。
- `app/service/chat_service.py`：内部核对阶段提示和正文阶段边界。
- `agent/core/graph/runtime_version.py`：缓存指纹覆盖核对逻辑、检索入口及SSE处理；旧答案不直接复用。
- `agent/core/__init__.py`、`core/workflow/__init__.py`：延迟导出，消除独立加载临床节点时的循环导入。
- `app/test/test_clinical_consistency.py`：原话来源、已知/未知、代码、修改定位、流式输出、缓存及检查点保护等回归。

## 验证证据

后端完整回归：**278项通过**（37.12秒），其中43项为本轮新增回归；Python编译检查通过。前端协议没有新增字段要求或新页面；仍使用既有SSE状态与正文格式。旧的第三方弃用提示仍在，不影响本轮检查结果。

直接模型探针使用五份合成文稿：未知应激源日期、虚构排除、GAD/惊恐标准混用、错误适应障碍编码、用户已提供的阴性心电图。最终五项均完成，前四类能修正，最后一类保留原意。探针也发现早期第二轮模型会否定正确修正、引入全类别监管结论，因而最终改为“一次模型校对＋修正后规则核验”，不是把第二个模型判断当作医学金标准。旧失败日志保留，没有改写成从未失败。

实际接口合成验收：症状/鉴别、多轮复述与两项补问、简洁药物审查、诊断到治疗完整链路。技术成功还需逐段核对正文；不能把HTTP完成当作医学内容正确。

## 资料出处及验证边界

诊断条件依据已封存并核对哈希的WHO CDDR 2024 PDF；出版信息见[WHO官方页面](https://www.who.int/publications/i/item/9789240077263)。使用位置为PDF284/印刷266、PDF289/印刷271、PDF302/印刷284、PDF370/印刷352。治疗建议须另核对实际治疗资料，不能由此把CDDR说成治疗指南。

本轮关闭的是上述可复现的软件与表述缺陷，不声称穷尽所有疾病、所有诊断编码、所有药物条件或所有未来模型输出。上游模型/服务不可用、上下文超限或修正后仍有矛盾时，系统保留失败状态，不把未核对文本当作成功答案，也不把这种情况伪装成专家已批准。
